## 背景

`save_it` の Zeabur テンプレートでは、セルフホスト版 Cobalt から Twitter/X の cookies を読み込ませる必要があります。これにより、ログインが必要な投稿やセンシティブ指定のコンテンツ、年齢確認などで制限された X のリソースもダウンロードできるようになります。

Cobalt 公式の Docker サンプルでは、環境変数 `COOKIE_PATH=/cookies.json` を指定し、ホスト側の `cookies.json` をコンテナ内の `/cookies.json` にバインドマウントする構成になっています。

一方で、Zeabur テンプレートの `volumes` は Docker Compose の「ファイル単体の bind mount」とは挙動が異なります。この違いを理解していないと、Cobalt が cookies を正しく読み込めません。

## 結論：Zeabur では cookies.json を Volume にしない

Zeabur の Volume は「ディレクトリ」をマウントする仕組みです。  
`volumes.dir: /cookies.json` のように、単一ファイルを想定したパスを指定すると、Zeabur は `/cookies.json` という「ディレクトリ」を作成・マウントしてしまいます。その結果、Cobalt から見ると `/cookies.json` はファイルではなくディレクトリになり、cookies ファイルとして読み込めません。

単一の設定ファイルをマウントしたい場合は、Zeabur の Config 機能（Config Editor / テンプレートの `configs`）を使うのが正しいやり方です。

### テンプレートでの設定例

```yaml
env:
  COOKIE_PATH:
    default: /cookies.json
    expose: false

configs:
  - path: /cookies.json
    template: |
      {
        "twitter": []
      }
    permission: 256
```

ここでは、環境変数 `COOKIE_PATH` に `/cookies.json` を指定しつつ、`configs` で `/cookies.json` を Zeabur 管理の設定ファイルとしてマウントしています。

## 持続性（Persistence）の考え方

通常のコンテナファイルシステム上で手動作成したファイルは、サービスの再起動や再デプロイのタイミングでイメージの初期状態に戻る可能性があります。  
Zeabur では、こうした設定ファイルを安全に持続させるために、用途に応じて次の 2 種類の仕組みを用意しています。

- **`volumes`：ディレクトリの永続化**  
  例：`/data` など、アプリケーションデータ一式を保存したいパス向け。
- **`configs`：単一設定ファイルの管理・マウント**  
  例：`/cookies.json` のような設定ファイル向け。

`configs` で管理されたファイルは、サービス起動時に Zeabur 側から指定パスへマウントされます。そのため、`/cookies.json` を cookies 用の設定ファイルとして扱う場合、Volume を追加で用意する必要はありません。`configs` で管理しておけば、再起動や再デプロイ後も同じ内容のファイルがマウントされ続けます。

## 実際の設定手順（Zeabur ダッシュボード）

Zeabur 上で Cobalt の cookies を設定する例を紹介します。ここでは Cobalt API サービスを `cobalt-api` として説明しますが、実際のサービス名に読み替えてください。

1. `cobalt-api` サービスの画面を開きます。
2. メニューから `Settings > Configs` を開きます。
3. パス `/cookies.json` の設定を作成または編集します。
4. 実際の cookies を JSON 形式で入力します。例：

   ```json
   {
     "twitter": [
       "auth_token=<token>; ct0=<csrf>"
     ]
   }
   ```

5. 設定を保存し、`cobalt-api` サービスを再起動します。

再起動後、コンテナ内の `/cookies.json` に Zeabur 管理のファイルがマウントされ、Cobalt は `COOKIE_PATH=/cookies.json` から X の cookies を読み込めるようになります。

## まとめ

- Zeabur の Volume は「ディレクトリ」単位で永続化する仕組みであり、`/cookies.json` のような単一ファイルには向きません。
- Cobalt の `COOKIE_PATH` に指定する cookies ファイルは、Zeabur の `configs`（Config Editor またはテンプレートの `configs`）で管理・マウントするのが適切です。
- `save_it` などの具体的なアプリケーションでは、Cobalt の cookies 設定ファイルを Zeabur Config で用意しておくことで、再デプロイ時にも安全に X のログイン状態を維持したダウンロード機能を提供できます。
