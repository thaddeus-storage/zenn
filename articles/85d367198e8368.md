Node.jsは今後のメジャーリリースでCorepackをデフォルト配布から外す予定とのことですが、これはCorepackが推奨されなくなるわけではありません。

むしろ、CorepackがNode.jsから独立することで、より柔軟に、そして迅速に進化できるようになるのではと感じています。多くの開発者が今もCorepackを愛用しており、今後も公式ドキュメントやダウンロードページから手軽に導入できます。今回の変更は、Node.js側のメンテナンス負担を減らしつつ、Corepackが独自に成長できる環境を整えるためのものだと受け取っています。

私自身もCorepackをこれからも使い続けるつもりです。Corepackはとても便利で、特に複数の異なる環境でnpmやyarn、pnpmなど様々なパッケージマネージャーを使い分ける方には、管理や切り替えが簡単になると感じています。

```sh
npm install --g yarn
```

```sh
npm install -g pnpm@latest-10

cd project_abc
npx pnpm@9 install

cd projec_xyz
npx pnpm@10 install
```

バージョンごとに異なるコマンドを気にするのは本当に面倒です。


ちなみに、私はantfu氏が開発した `ni` も活用しています。

https://github.com/antfu-collective/ni

```sh
ni vite

# npm i vite
# yarn add vite
# pnpm add vite
# bun add vite
# deno add vite
```

```sh
ni --frozen

# npm ci
# yarn install --frozen-lockfile (Yarn 1)
# yarn install --immutable (Yarn Berry)
# pnpm install --frozen-lockfile
# bun install --frozen-lockfile
# deno install --frozen
```

`ni` を使うことで、どのパッケージマネージャーを使っているかをあまり意識せず、より快適に開発できるようになりました。Corepackとniの組み合わせは、現代のJavaScript開発において、とても頼もしいツールだと思います。
